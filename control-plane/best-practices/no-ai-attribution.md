# No AI attribution in commits or PRs

## Rule

Do not credit the AI tool, model, or session in commit messages, PR titles, PR descriptions, or code comments. Write commits as the operator of record — the person who reviewed, validated, and accepted the change.

## Why

Commit messages are production artifacts that answer "why does this change exist?" — not "how was it produced?". AI attribution displaces that signal with provenance noise. It also creates ambiguity in code review (was this reviewed by a human?) and may complicate compliance, attribution, and licensing checks on shared or regulated repos.

The operator is accountable for every change that lands. The commit message should reflect that accountability, not distribute it to a tool.

## How to apply

- Write commit messages in first-person active voice as if you are the sole author.
- PR descriptions document the *change* and *rationale*, not the production method.
- If the AI session produced something unexpected that the operator corrected, the correction belongs in the commit body — not the tooling provenance.
- `Suggested-by:` trailers for external collaborators (humans) remain appropriate. AI tool trailers are not.

## Anti-patterns

| ❌ Avoid | ✅ Prefer |
|---|---|
| `Generated by Claude` | *(omit)* |
| `Co-authored-by: Claude AI <noreply@anthropic.com>` | *(omit)* |
| `AI-assisted commit` | *(omit)* |
| `claude helped write this` | *(omit)* |

> This rule applies to commits and PR copy. Internal scratchpads and work logs may document tooling provenance freely — that context belongs in ephemeral notes, not in version-controlled history.
