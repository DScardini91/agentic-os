# Post-MVP Expansion Directive

## Status
Once the MVP phase is validated (one domain stable, agents predictable, output trusted), the system enters **Controlled Scale-Up Mode**.

## Expansion principle
Every expansion must satisfy at least one of:
1. Reduces real operational friction
2. Improves decision quality
3. Improves visibility or navigation
4. Reduces repeated manual work
5. Supports a real use case already emerging in practice
6. Makes the system more usable across domains

## Scale-up order (default — adjust to your priorities)
| Phase | Domain | Focus |
|---|---|---|
| 1 | Professional | Stabilize — client model, project model, reviews |
| 2 | `<second-priority>` | `<focus>` |
| 3 | Personal + Learning | Household, health, craft, travel, knowledge |
| 4 | Finance | Cash flow, budgeting, reimbursements |
| 5 | Investments | Thesis, watchlist, portfolio review |

## Database evolution rule
Add a new database/table only when ALL THREE: artifact type genuinely distinct · workflow constrained · creates practical clarity.

## Agent evolution rule
Add a new agent only when ALL THREE: role meaningfully distinct · reduces reasoning burden · clear ownership boundaries.

## Instruction priority
This directive supersedes prior MVP-only restrictions whenever they conflict.
